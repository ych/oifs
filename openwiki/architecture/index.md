# Files

- [Async I/O & Read Engines](async_io_and_engines.md)
- [Block & Inode Allocation](block_allocation.md) - Describes the two-bitmap allocator (inode bitmap, data bitmap), the search-hint optimization (free_block_hint, free_inode_hint), the AllocSim used by journaled operations to simulate allocations against bitmap copies, and the contiguous-run allocator for seekable chunked files.
- [Compression and Pre-compression Filters](compression_and_filters.md) - How OIFS combines zstd compression (with multi-frame EOF append, seekable 64K chunked compression with COW extent swap, and read-modify-recompress fallback) with Blosc2-style pre-compression filters (Delta, ByteShuffle, BitShuffle, TruncPrecision). Covers the Zstd thread-local pool, persistent scoped worker pool, DecodedBlobCache (4 slots, 16 MiB/entry, 32 MiB cap) for non-seekable reads, ChunkReadCache (8 slots) for seekable reads, and cache invalidation across write, truncate, delete, migrate, defrag, and reload.
- [Concurrency & Session Model](concurrency_and_session.md) - The OifsSession abstraction with three modes — Standalone (direct mmap, zero IPC), Local (Unix Domain Sockets in per-user private directory), Network (TCP + rendezvous file with clock-free active Ping/Pong) — master election via bind_or_connect, transparent failover, session registry with canonical path dedup, poison-recovered locks for registries/caches, and length-prefixed Bincode IPC frame protocol with challenge-response authentication.
- [Online Defragmentation](defragmentation.md) - How OIFS analyzes filesystem fragmentation using 64-bit bitmap scanning and performs both safe (out-of-place rebuild with atomic rename) and WAL-atomic in-place defragmentation, including ChunkEntry relocation for seekable files and a background auto-defrag coordinator.
- [DiskManager & Persistence](disk_manager_and_persistence.md)
- [Encryption & Key Hierarchy](encryption.md) - Argon2id key derivation (m=64MiB, t=3, p=4), BLAKE2b domain-separated subkeys (payload, filename_siv, filename_cipher, ipc_auth), XChaCha20-Poly1305 for payloads, SIV + AEAD for filenames (synthetic nonce from BLAKE2b), context-bound AEAD (file_aad, chunk_aad binding inode_id, chunk_idx, flags), NEON + short-scalar XChaCha20 optimization, and the two scheme versions (legacy empty AAD vs context-bound).
- [C FFI Interface](ffi_interface.md) - How OIFS exposes its storage engine as a standard C shared library (liboifs) through an opaque handle model, callback-driven directory iteration, zero-copy offset reads, pluggable I/O backend configuration, version handshake, and thread-safe error reporting.
- [Inodes & Directories](inode_and_directory.md) - Detailed specification of OIFS's 256-byte inode structure (format v2), directory entry format with filename encryption (SIV + XChaCha20-Poly1305), block pointer hierarchy, DirIndex promotion logic, and ShardedDirCache.
- [Filesystem Integrity Checking (fsck)](integrity_checking_fsck.md) - How the OIFS fsck structural consistency scanner performs set-theoretic verification between bitmap allocation states and directory reachability to detect orphan inodes, leaked blocks, missing blocks, and cross-linked blocks.
- [Metadata WAL / Journaling](journal.md) - Describes the transactional metadata write-ahead log (WAL) that ensures crash resilience, including its circular buffer design, CRC32C protection, idempotent redo replay, JBD2-style deferred checkpointing under Strict durability, and DurabilityMode semantics.
- [MCP Server Integration](mcp_server.md) - How the oifs_mcp binary exposes the OIFS storage engine as Model Context Protocol (MCP) tools over stdio, providing AI agents with an isolated, single-file virtual filesystem for persistent memory.
- [OIFS Architecture Overview](overview.md) - High-level architectural overview of OIFS (O's Inode File System), detailing its single-file on-disk image model, module layout, multi-target crate compilation, and subsystem interactions across CLI, C FFI, and MCP entry points.
