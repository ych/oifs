# Files

- [Async I/O Engine and Group Commit](async_io_and_engines.md) - Covers the pluggable I/O backend system (Mmap, Pread, IoUring), ExtentList coalescing, io_uring capability gating, async read engine with inline fast-path, and async write engine with group commit for DurabilityMode::Strict.
- [Block & Inode Allocation](block_allocation.md) - Documents the sequential hint-based block and inode allocator (SimpleBlockAllocator), multi-block bitmap layout (v3), hardware-accelerated tzcnt scanning, BitmapSliceMut write-through mirrors for FileIo mode, and allocation rollback on WAL failure.
- [Compression and Pre-compression Filters](compression_and_filters.md) - How OIFS combines zstd compression (with multi-frame EOF append, seekable 64K chunked compression with COW extent swap, and read-modify-recompress fallback) with Blosc2-style pre-compression filters (Delta, ByteShuffle, BitShuffle, TruncPrecision). Covers the Zstd thread-local pool, persistent scoped worker pool, DecodedBlobCache (4 slots, 16 MiB/entry, 32 MiB cap) for non-seekable reads, ChunkReadCache (8 slots) for seekable reads, and cache invalidation across write, truncate, delete, migrate, defrag, and reload.
- [Concurrency & Session Model](concurrency_and_session.md) - The OifsSession abstraction with three modes — Standalone (direct mmap, zero IPC), Local (Unix Domain Sockets in per-user private directory), Network (TCP + rendezvous file with clock-free active Ping/Pong) — master election via bind_or_connect, transparent failover, session registry with canonical path dedup, poison-recovered locks for registries/caches, and length-prefixed Bincode IPC frame protocol with challenge-response authentication.
- [Online Defragmentation](defragmentation.md) - How OIFS analyzes filesystem fragmentation using 64-bit bitmap scanning and performs both safe (out-of-place rebuild with atomic rename) and WAL-atomic in-place defragmentation, including ChunkEntry relocation for seekable files, shift_table_collapse for chunk table compaction, and a background auto-defrag coordinator.
- [DiskManager & Persistence](disk_manager_and_persistence.md)
- [Encryption & Key Hierarchy](encryption.md) - Argon2id key derivation (m=64MiB, t=3, p=4), BLAKE2b domain-separated subkeys (payload, filename_siv, filename_cipher, ipc_auth), XChaCha20-Poly1305 for payloads, SIV + AEAD for filenames (synthetic nonce from BLAKE2b), context-bound AEAD (file_aad, chunk_aad binding inode_id, chunk_idx, flags), NEON + short-scalar XChaCha20 optimization, IPC challenge-response authentication, and the two scheme versions (legacy empty AAD vs context-bound).
- [C FFI Interface](ffi_interface.md)
- [FUSE Kernel Protocol Engine](fuse_engine.md) - Pure-Rust FUSE ABI v7.28 implementation with frame parser/dispatcher, cross-platform mount runners (Linux /dev/fuse + fusermount3, macOS FUSE-T/macFUSE via SCM_RIGHTS), dynamic max_write negotiation, handle table, read-only enforcement, UTF-8 NFD->NFC normalization, and macOS Finder metadata storm protection.
- [Inodes & Directories](inode_and_directory.md) - Detailed specification of OIFS's 256-byte inode structure (format v2), directory entry format with filename encryption (SIV + XChaCha20-Poly1305), block pointer hierarchy, DirIndex promotion logic, 32-shard ShardedDirCache, and FUSE filename normalization.
- [Filesystem Integrity Checking (fsck)](integrity_checking_fsck.md) - How the OIFS fsck structural consistency scanner performs set-theoretic verification between bitmap allocation states and directory reachability to detect orphan inodes, leaked blocks, missing blocks, and cross-linked blocks, plus read-only journal cleanliness verification.
- [Metadata WAL / Journaling](journal.md) - Describes the transactional metadata write-ahead log (WAL) that ensures crash resilience, including its circular buffer design, CRC32C protection, idempotent redo replay, JBD2-style deferred checkpointing under Strict durability, and DurabilityMode semantics.
- [MCP Server Integration](mcp_server.md) - How the oifs_mcp binary exposes the OIFS storage engine as Model Context Protocol (MCP) tools over stdio, providing AI agents with an isolated, single-file virtual filesystem for persistent memory.
- [OIFS Architecture Overview](overview.md) - High-level architectural overview of OIFS (O's Inode File System), detailing its single-file on-disk image model, module layout, multi-target crate compilation, and subsystem interactions across CLI, C FFI, MCP, and FUSE entry points.
- [Atomic Rename and Metadata Operations](rename_and_atomic_ops.md) - Documents the atomic POSIX rename implementation with WAL transactions, SIV re-encryption for cross-directory moves on encrypted filesystems, FUSE_RENAME/RENAME2 opcode handling, and the MetadataOp journal framing for create/delete/mkdir/rename.
- [Superblock and On-Disk Layout](superblock_and_layout.md) - Comprehensive documentation of the OIFS superblock structure, format versioning (v1/v2/v3), block layout geometry, journal region placement, encryption fields, and migration cursor mechanics for in-place format upgrades.
