# Files

- [Async I/O Engine and Group Commit](async_io_and_engines.md) - Covers the pluggable I/O backend system (Mmap, Pread, IoUring), ExtentList coalescing, io_uring capability gating, async read engine with inline fast-path, and async write engine with group commit for DurabilityMode::Strict.
- [Block & Inode Allocation](block_allocation.md) - Documents the bitmap-based block allocator (SimpleBlockAllocator), inode allocator, free space tracking, allocation strategies (hints, contiguous runs), multi-block bitmap layout (v3), hardware-accelerated tzcnt scanning, BitmapSliceMut write-through mirrors for FileIo mode, and allocation simulation for WAL transactions.
- [Compression & Pre-Compression Filters](compression_and_filters.md) - Seekable 64 KiB chunked compression (Zstd), SIMD pre-filters (Delta, Shuffle, BitShuffle, TruncPrecision), ZstdContextPool with persistent scoped worker pool, DecodedBlobCache and ChunkReadCache for read acceleration, and cache invalidation across write/truncate/defrag.
- [Concurrency and session](concurrency_and_session.md)
- [Online Defragmentation and Auto-Defrag](defragmentation.md) - How OIFS analyzes filesystem fragmentation using 64-bit bitmap scanning and performs both safe (out-of-place rebuild with atomic rename) and WAL-atomic in-place defragmentation, including ChunkEntry relocation for seekable files, shift_table_collapse for chunk table compaction, and a background auto-defrag coordinator.
- [DiskManager & Persistence](disk_manager_and_persistence.md) - Central coordinator for OIFS storage: image open/create, superblock management, inode CRUD, data read/write with compression/encryption, durability modes, flush/msync, read-only mounts, and atomic rename.
- [Encryption & Filename Obfuscation](encryption.md) - Argon2id KDF, BLAKE2b-512 subkeys, XChaCha20-Poly1305 AEAD for data, 192-bit SIV for filenames, and key management.
- [C FFI and C++17/20 API Surface](ffi_interface.md) - Documents the public C FFI (oifs.h) and modern C++ header-only API (oifs.hpp): opaque handles, error codes, sync/async operations, PinnableSlice zero-copy views, and co_await integration.
- [FUSE Kernel Protocol Engine](fuse_engine.md) - Pure-Rust FUSE ABI v7.28 implementation with frame parser/dispatcher, cross-platform mount runners (Linux /dev/fuse + fusermount3, macOS FUSE-T/macFUSE via SCM_RIGHTS), dynamic max_write negotiation, handle table, read-only enforcement, UTF-8 NFD->NFC normalization, and macOS Finder metadata storm protection.
- [Inode Layout and Multi-Block Directories](inode_and_directory.md) - Detailed specification of OIFS's 256-byte inode structure (format v2), directory entry format with filename encryption, block pointer hierarchy, multi-block directory structure with SipHash-2-4 indexing, and directory entry encoding.
- [Filesystem Integrity Checking (fsck)](integrity_checking_fsck.md) - How the OIFS fsck structural consistency scanner performs set-theoretic verification between bitmap allocation states and directory reachability to detect orphan inodes, leaked blocks, missing blocks, and cross-linked blocks, plus read-only journal cleanliness verification. Covers chunk reference validation, deduplication detection, repair strategies, and verification flow.
- [Metadata WAL / Journaling](journal.md) - Describes the transactional metadata write-ahead log (WAL) that ensures crash resilience, including its circular buffer design, CRC32C protection, idempotent redo replay, JBD2-style deferred checkpointing under Strict durability, and DurabilityMode semantics.
- [MCP Server (oifs_mcp)](mcp_server.md) - How the oifs_mcp binary exposes the OIFS storage engine as Model Context Protocol (MCP) tools over stdio, providing AI agents with an isolated, single-file virtual filesystem for persistent memory.
- [Architecture Overview](overview.md) - High-level system map showing owned subsystems, runtime domains, and cross-system data flows for OIFS.
- [Atomic Rename and Metadata Operations](rename_and_atomic_ops.md) - Documents the atomic POSIX rename implementation with WAL transactions, SIV re-encryption for cross-directory moves on encrypted filesystems, FUSE_RENAME/RENAME2 opcode handling, and the MetadataOp journal framing for create/delete/mkdir/rename.
- [Storage Engines](storage_engines.md) - OIFS dual storage backends—Mmap for zero-copy memory-mapped I/O and FileIo for pure positional pread/pwrite I/O—operating over the exact same on-disk format.
- [Superblock and On-Disk Layout](superblock_and_layout.md) - Comprehensive documentation of the OIFS superblock structure, format versioning (v1/v2/v3), block layout geometry, journal region placement, encryption fields, and migration cursor mechanics for in-place format upgrades.
