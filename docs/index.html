OIFS — O's Inode File System

A high-performance, single-file containerized POSIX filesystem written in Rust. Pack directories, compressed scientific arrays, encrypted agent workspaces, or application assets into a single portable .img file with crash-safe WAL, multi-process concurrency, and native OS mounting.

Core Capabilities

Dual Storage Engine (Mmap & FileIo)

Zero-copy mmap (48–51 GB/s cached reads) plus an opt-in 100% mmap-free positional pread/pwrite engine with 64-shard page caching and io_uring support.

Zero-Kext NFSv3 & Pure-Rust FUSE

Mount any .img natively on macOS without third-party kexts via the built-in loopback NFSv3 server, or via pure-Rust FUSE ABI v7.28 on Linux and macFUSE.

SIMD Compression & Seekable 64K

NEON/SSE2 Delta, Byte Shuffle, BitShuffle, and TruncPrecision pre-filters paired with pooled Zstd for up to 390× scientific telemetry compression and random read_at.

Authenticated Encryption & WAL

Hardened Argon2id KDF, context-bound XChaCha20-Poly1305 AEAD, 192-bit SIV filename encryption, and optional CRC32C metadata Write-Ahead Logging with automatic recovery.

Cross-Image CoW Clone & Fast Transfer

O(1) whole-image clones (clonefile / FICLONE) and a 3-tier cross-image transfer & sub-range splice pipeline (FICLONERANGE → copy_file_range → raw block copy).

C/C++ Zero-Copy API & AI MCP Server

Header-only Modern C++17/20 wrapper (oifs.hpp with C++20 co_await & PinnableSlice), C FFI (oifs.h), built-in MCP server, and 113 Kani formal verification proofs.

Quick Start

# Install CLI directly from GitHub
cargo install --git https://github.com/ych/oifs --tag 1.4.0

# Create a crash-safe journaled image and store files
oifs -i workspace.img create --size 100 --journal
oifs -i workspace.img put ./data.bin /datasets/data.bin --chunked --filter bitshuffle

# Mount natively (macOS uses built-in zero-kext NFSv3; Linux uses FUSE)
oifs -i workspace.img mount ./mnt --foreground
