# Files

- [Asynchronous I/O and Pluggable Engines](async_io_and_engines.md) - Pluggable payload read engine supporting Mmap, Pread, and io_uring with ExtentList coalescing, ring pooling, and kernel gating.
- [Block Allocation and Bitmap Indexing](block_allocation.md) - How OIFS allocates and tracks data blocks and inodes with 64-bit bitmap scanning, allocation hints for amortized O(1) sequential allocation, and the single/double/triple indirect block addressing scheme that expands files up to ~513GB.
- [Compression and Pre-compression Filters](compression_and_filters.md) - How OIFS combines zstd compression (with multi-frame EOF append, seekable 64K chunked compression with COW extent swap, and read-modify-recompress fallback) with Blosc2-style pre-compression filters (Delta, ByteShuffle, BitShuffle, TruncPrecision).
- [Concurrency, Sessions, and IPC](concurrency_and_session.md) - How OIFS allows multiple processes to share one image through a Master-Proxy design — a single Master holds the mmap with an RwLock and sync_mutex while Proxies forward framed requests over UDS or TCP — coordinated by the OifsSession registry with self-healing master-failover and POSIX OpenMode semantics.
- [Online Defragmentation](defragmentation.md) - How OIFS analyzes filesystem fragmentation using 64-bit bitmap scanning and performs safe defragmentation via an out-of-place rebuild with preserved compression, filters, and a transactional 3-step atomic rename with rollback.
- [DiskManager and Persistence Model](disk_manager_and_persistence.md) - How OIFS encapsulates memory-mapped I/O, RwLock concurrency, pluggable async I/O engines (Mmap, Pread, io_uring), configurable durability policies, zero-copy reads, and the integrated write pipeline inside DiskManager.
- [Encryption Subsystem](encryption.md) - How OIFS provides authenticated at-rest data confidentiality and deterministic directory privacy using XChaCha20-Poly1305 AEAD, Argon2id key derivation, Zeroize key hygiene, and Blake2b-tweak SIV filename encryption.
- [C FFI Interface](ffi_interface.md) - How OIFS exposes its storage engine as a standard C shared library (liboifs) through an opaque handle model, callback-driven directory iteration, zero-copy offset reads, pluggable I/O backend configuration, thread-safe error reporting, and version handshake for ABI stability.
- [Inode and Directory Management](inode_and_directory.md) - How OIFS implements Unix-like inode architecture, manages directory entries, handles dynamic multi-block directories, and maintains second-precision timestamps.
- [Filesystem Integrity Checking (fsck)](integrity_checking_fsck.md) - How the OIFS fsck structural consistency scanner performs set-theoretic verification between bitmap allocation states and directory reachability to detect orphan inodes, leaked blocks, missing blocks, and cross-linked blocks.
- [Inter-Process Communication (IPC)](ipc.md) - The IPC subsystem enables transparent master-proxy coordination with dual transport backends (Unix Domain Sockets and Network TCP) and provides master election, framed RPC, and a request dispatcher for OIFS file system operations.
- [Journaling and Write-Ahead Log](journal.md) - Document the transactional metadata Write-Ahead Log (WAL) that provides crash resilience and durability, including journal handling, recovery, and durability policies.
- [MCP Server Integration](mcp_server.md) - How the oifs_mcp binary exposes the OIFS storage engine as Model Context Protocol (MCP) tools over stdio, providing AI agents with an isolated, single-file virtual filesystem for persistent memory.
- [OIFS Architecture Overview](overview.md) - High-level architectural overview of OIFS (O's Inode File System), detailing its single-file on-disk image model, module layout, multi-target crate compilation, and subsystem interactions across CLI, C FFI, and MCP entry points.
- [SuperBlock and On-Disk Layout](superblock_and_layout.md) - How OIFS defines its fixed on-disk physical geometry, SuperBlock magic validation, inode table sizing rules, backward compatibility guarantees, and Kani formal layout verification.
